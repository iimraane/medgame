# Pharmacy campaign and case generation

## Core loop

The chosen loop is **everyday need**. The client comes to the counter with a concrete routine situation, not a symptom inventory intended to make the player infer a diagnosis. Examples will be selected only once the catalogue is designed: preparing a trip, managing a known minor need, protecting a situation, replacing an unsuitable habit, or choosing an appropriate self-care product.

The intended player sequence is:

1. Understand the stated need and ask contextual questions.
2. Separate a suitable self-care response from a request that needs orientation.
3. Select a product or another catalogued safe action.
4. Submit concise dispensing counsel.
5. Receive a scored debrief.

## Client variation

Every generated pharmacy client reuses the project’s **complete existing personality system**, not only two shared traits. The generation layers compatible components from all existing sources: shared behavioural traits, active personality/modifier categories, scenario response style, and optional non-verbal cues. They affect phrasing, confidence, recall, urgency, and willingness to answer questions, never the canonical product/action outcome.

The case data must keep these axes separate:

| Axis | Owned by | Purpose |
| --- | --- | --- |
| Need and relevant context | Pharmacy case | Determines valid product/action and critical counselling topics. |
| Personality stack | Shared traits, existing modifiers, response style, and non-verbal cues | Changes the conversation presentation only. |
| Difficulty | Level/case | Controls ambiguity and what the player must discover. |
| Outcome rubric | Server catalog | Defines exact, near, unsuitable, and orientation outcomes. |

## Deferred design work

- Exact specialities, forms, and authoritative sources for every proposed product.
- Final acceptance of the tool cadence and tool labels.
- Case templates for every product; no generated case may lack a valid dispensing answer.
